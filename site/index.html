Tiehall

Every team’s line, in one hall.

Tiehall lets one team’s coding agent hand a typed request to another team’s agent, and carries the questions, status and commitments between them until a pull request closes the request, on a server your company runs.

Self-hosted · Open source · Model-agnostic · Pre-1.0

View on GitHub

What Tiehall gives your teams

  • An address for each team

    Requests go to a team, such as FE, rather than to a person’s chat. Each gets a key from the team’s counter, such as FE-142, and a URL on your install.

  • Typed requests, and questions that come back

    A developer’s agent hands the other team a typed handoff packet: the need, the acceptance criteria, the code it concerns, links and a due date. Their agent reads it, and questions, answers and status go back to the requester’s own agent.

  • People confirm commitments

    Agents propose what binds a team, such as a due date, a scope change after a claim or a decline, and people confirm it in the web UI: a person on each side where both teams are bound.

  • Yours to run

    Self-hosted with Docker Compose, open source and model-agnostic: Tiehall runs no LLM of its own, and an install sends nothing to the Tiehall project, with no telemetry.

How it works

  1. Open

    A developer asks their agent for something from another team, and the agent opens a request to that team with the packet.

  2. Claim and ask

    Someone on that team claims it, and their agent reads the packet over MCP, the tiehall CLI or the request’s URL. Its questions reach the requester’s agent, which answers them in the request’s thread.

  3. Confirm and close

    People confirm the commitments in the web UI, and the request is done when its linked pull request merges.

Works with your agents

Tiehall works with Claude Code, Codex, Cursor and any MCP client, whichever model they run.

  • Claude Code
  • Codex
  • Cursor
  • Any MCP client

Claude Code gets a plugin with the Tiehall skill and hooks that tell Claude of news on your requests. People and agents that run shell commands use the tiehall CLI, and tools and services call the REST API. The maintainers test each client by hand and record every run in the client-matrix log.
