# Tasks

One group, in milestone M2 "The rest of v1" of the main change, `add-tiehall-oss-v1`, built before its group 29 publishes the first release. This change waits for the maintainer's approval (D57): none of its tasks is built until the maintainer has approved it, and an item the maintainer changes in "Decisions to approve" changes the task that builds it. The order: the assets, the stylesheet and the mark (1.1 to 1.3); the policy of each kind of page, then the shell, first in the web role's pages and then in the pages Next.js renders (1.4 to 1.6); the page families, the request page's activity first (1.7 to 1.11); the live hall's reads (1.12, 1.13); the live hall's page and its script (1.14, 1.15); the screenshot tests (1.16); the docs (1.17); and the text corrections and the check of the change (1.18, 1.19).

Tasks read as in the main change's tasks.md: the checkbox line is the whole task, with what to build, how it is verified and, in brackets, the requirements it implements; tests come first, and a test written ahead of the task that makes it pass is committed as an expected failure (`it.fails` or `test.todo`) until that task. Rules for every task:
- A task that adds a route file under `apps/web/app` names it in `packages/commands/test/web-ui-hosts-browser.test.ts` in the same commit, with the paths that show it, so that test visits it and still fails on any request to another host.
- A task that changes a page's markup or policy updates, in the same commit, the existing tests that assert the old markup or the old policy string, among them `review-page.test.ts`, `consent-screen.test.ts`, `refusal-pages.test.ts`, `setup-code.test.ts`, `setup-github-app.test.ts`, `request-content-browser.test.ts`, `request-urls.test.ts`, `intake-pages.test.ts`, `apps/web/test/api-changelog.test.ts` and `tools/image-tests/test/image.test.ts`, keeping what each asserts about framing, forms and scripts.
- Browser suites run the installed Chrome through `playwright-core` (T17) and set hook timeouts of 300 seconds and test timeouts of 120 seconds, so they hold on slow CI runners; waits on the page use the suite's polling helpers, never fixed sleeps, except where a task measures a time bound.
- The live hall's reads and the request page's activity are internal commands: `openapi/v1.json`, `mcp/tools.json` and the packet schema do not change, and `pnpm check:openapi`, `pnpm check:mcp-tools` and `pnpm check:packet-schema` pass unchanged after every task.
- Comments in the code cite this change's requirements as `web-ui: <Requirement name>` and its design as `design.md, Design: <section>` with D57, and `pnpm test` runs the source-citation check over them.
