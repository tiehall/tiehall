This change waits for the maintainer's approval (D57): none of its tasks is built until the maintainer has approved it, and an item the maintainer changes in "Decisions to approve" changes the task that builds it. The maintainer approved it on 2026-10-12 (D61), with two departures, which tasks 1.16 and 1.17 build: the system's own fonts in place of IBM Plex, which tasks 1.1 and 1.2 had kept, and a gold New request in place of the navy one of task 1.5. The order: the assets, the fonts, the stylesheet and the mark (1.1 to 1.3); the policy of each kind of page, then the shell, first in the web role's pages and then in the pages Next.js renders (1.4 to 1.6); the page families, the request page's activity first (1.7 to 1.11); the live hall's reads (1.12, 1.13); the live hall's page and its script (1.14, 1.15); the two departures of the approval, D61 (1.16, 1.17); the screenshot tests (1.18); the docs (1.19); and the text corrections and the check of the change (1.20, 1.21).

Tasks read as in the main change's tasks.md: the checkbox line is the whole task, with what to build, how it is verified and, in brackets, the requirements it implements; tests come first, and a test written ahead of the task that makes it pass is committed as an expected failure (`it.fails` or `test.todo`) until that task. Rules for every task:
- A task that adds a route file under `apps/web/app` names it in the page inventory in the same commit, with the paths that show it, so `web-ui-hosts-browser.test.ts` visits it and still fails on any request to another host: before task 1.4 in that test's `PAGES`, `SIGNED_OUT_PAGES` or `NOT_PAGES`, and from task 1.4 on in `packages/commands/test/support/page-inventory.ts`, where task 1.4 moves them.
- A task that changes a page's markup or policy updates, in the same commit, the existing tests that assert the old markup or the old policy string, among them `review-page.test.ts`, `consent-screen.test.ts`, `refusal-pages.test.ts`, `setup-code.test.ts`, `setup-github-app.test.ts`, `request-content-browser.test.ts`, `request-urls.test.ts`, `intake-pages.test.ts`, `apps/web/test/api-changelog.test.ts`, `apps/web/test/proxy.test.ts` and `tools/image-tests/test/image.test.ts`, keeping what each asserts about framing, forms and scripts.
- Browser suites run the installed Chrome through `playwright-core` (T17) and set hook timeouts of 300 seconds and test timeouts of 120 seconds, so they hold on slow CI runners; a test that watches a page for a minute sets its own timeout of 240 seconds; waits on the page use the suite's polling helpers, never fixed sleeps, except where a task measures a time bound.
- "The markup a page is served with" is the HTML of the page's answer, before any script runs; a check of the page's DOM after its scripts ran is named as such.
- A control is at least 24 by 24 CSS pixels wherever a task checks it, apart from a link inside a sentence or a block of text, as WCAG 2.2 success criterion 2.5.8 allows.
- The live hall's reads, the shell's read and the request page's activity are internal commands: `openapi/v1.json`, `mcp/tools.json` and the packet schema do not change, and `pnpm check:openapi`, `pnpm check:mcp-tools` and `pnpm check:packet-schema` pass unchanged after every task.
- Comments in the code cite this change's requirements as `web-ui: <Requirement name>` and its design as `design.md, Design: <section>` with D57, and `pnpm test` runs the source-citation check over them.
