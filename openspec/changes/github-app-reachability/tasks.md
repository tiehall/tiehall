# Tasks

One group, in milestone M1 "It works" of the main change, `add-tiehall-oss-v1`. Most of the work it changes is not built yet: the GitHub stub (7.3), the manifest flow (7.4), the manifest allowlist test (7.5), setup completion (7.9), group 10 (webhooks, installations, modes and polling), `setup reopen` (21.2), the install docs (21.9) and the admin page's integration state (21.10) in M1, and close on merge (23.15) and the broken-installation banner (24.11) in M2. So these tasks are built together with, or right after, those main tasks, and each names the main task it extends. Three points of order: the first step of 1.1, which commits the spike's recorded answers as fixtures, comes before the main change's task 1.10 deletes the spike branches; the listing module of 1.5 is built before 7.9, because 1.6 needs it, while its hooks into the poll, the reconciliation job and the admin page come with 10.8, 10.9 and 10.3; and the cases a task adds to a main task that is not built yet, such as 1.6's cases for 21.2, are written with that task. Some of the work changes built code: the settings reader (5.1, `packages/commands/src/settings.ts`), the log redaction (4.14, `packages/commands/src/log.ts`), the setup gate (7.1, `packages/commands/src/setup-gate.ts`, its test, and the comment in `apps/web/proxy.ts`), the setup route (7.2, `packages/commands/src/setup-route.ts`, whose next step becomes the App step), and the committed lists of the confirmation coverage check (8.4, `tools/repo-checks/confirmation-actions.json`) and of the security-event coverage check (20.1, `tools/repo-checks/security-events.json`). Where a main task's text differs from this change, such as 7.4's active webhook on every install, 7.5's five subscribed events and 10.4's covered repositories from deliveries only, this change's tasks govern.

Tasks read as in the main change's tasks.md: the checkbox line is the whole task, with how it is verified and, in brackets, the requirements it implements; tests come first and are committed as expected failures (`it.fails` or `test.todo`) until the task that makes them pass; a task marked **(founder step: …)** holds a step that only the founder can do.
